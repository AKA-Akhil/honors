# DECISIONS

- Python: system default is 3.14 (no llama-cpp wheels), so the venv uses Python 3.12.3 (`.venv`).
- llama-cpp-python 0.3.36 prebuilt CUDA wheel (cu124 index) installed; it additionally needs `nvidia-cuda-runtime-cu12`, `nvidia-cublas-cu12` pip packages whose DLL dirs are registered in `config.add_cuda_dll_dirs()`. CUDA offload verified (RTX 4050, 6 GB).
- Hugging Face Xet download backend stalled; downloads use `HF_HUB_DISABLE_XET=1`. Link speed is only ~1 MB/s, so downloads are ordered by priority (see `scripts/01_download_models.py`) and inference starts as files arrive.
- `bartowski/Llama-3.2-3B-Instruct-GGUF` has no `Q2_K` and no `Q3_K_M` file. Per fallback ladder step 1, Llama-3.2-3B uses `unsloth/Llama-3.2-3B-Instruct-GGUF`, which has all five levels (single repo for all levels of a model, to avoid mixing quantizer pipelines). Qwen2.5-3B stays on bartowski (has all five).
- `create_chat_completion(logprobs=True)` raises ValueError when the model is loaded with `logits_all=False` (the spec's loading setting). Used Fallback A variant: format the prompt with the GGUF's own Jinja chat template, evaluate it, and read the **full next-token logits** from the llama.cpp context (`llm._ctx.get_logits()`), softmax over the whole vocabulary, and sum the probability of every token whose stripped/lowercased text is "yes" (resp. "no"). This is exact (no top-20 truncation) and keeps `logits_all=False`. Sanity check: p_yes varies (0.00-0.98) and tracks qualification tier.
- Measured latency ~0.1 s/prompt, so the full 4,000-prompt run takes well under 1 h; no Section 10 inference reductions are needed. The only bottleneck is the ~0.3-1 MB/s download link.
- Each template has 200 prompts per run (50 resumes x 4 variants); the spec's "400 per model per level" is the two templates together. 20 runs x 200 = 4,000 prompts.
- Bootstrap CI and Wilcoxon p-values can disagree (heavy-tailed per-resume gaps: most near 0, few large); both are reported, and the paper says so.
- Holm correction family for gaps = all 40 gap tests (2 models x 5 levels x 2 templates x {gender, race}); for flips = McNemar tests per threshold type; chi-square tests separately.
- Chi-square test of Yes->No flips by group is only computed when there are >= 4 Yes->No flips (otherwise NaN, shown "--").
- Reference-calibrated threshold implemented exactly as specified (median Q8_0 P(Yes)); it is degenerate for Qwen Q2_K (selects everyone) and is reported with that caveat. Main flip/selection results use threshold 0.5.
- No pdflatex/LaTeX installation was available and none was installed (slow link), so main.tex was NOT compiled; `scripts/check_tex.py` statically verifies cite keys, labels, environments, inputs and figures instead.
- Model files in models/ (22 GB) were kept so everything can be re-run; delete the folder to free disk space.
- Paper tables (paper/tables/*.tex/.md) are generated by scripts/06_paper_tables.py; paper/main.md is built from paper/main_template.md by scripts/07_build_md.py; scripts/check_numbers.py cross-checks headline numbers against results/tables.
